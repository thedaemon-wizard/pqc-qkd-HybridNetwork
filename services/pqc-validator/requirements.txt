# Pinned EXACTLY, and coupled to submodules/liboqs (tag 0.16.0), which the
# Dockerfile builds and installs to /opt/liboqs.
#
# liboqs-python never refuses a liboqs it finds; it only warns when major.minor
# differ, so any other mismatch shows up as a missing ctypes symbol or a crash
# rather than a clear error -- and a range would let the two drift apart
# silently. Bump this and the
# submodule together.
#
# The previous `>=0.14.0,<0.16` was a speculative cap from the initial commit.
# It became unsatisfiable when PyPI stopped publishing anything below 0.16.0,
# and the image could no longer be built at all.
# 0.16.0.1 (2026-09-23) is a maintenance release "still built for liboqs 0.16.0"
# that fixes GHSA-pw23-r5gj-42g8: shell command injection in the AUTOMATIC liboqs
# install that runs when no liboqs is found at import. This image never takes that
# path -- the Dockerfile builds liboqs from the submodule into /opt/liboqs -- so the
# bump is for hygiene, and it keeps the version coupling above intact.
liboqs-python==0.16.0.1
